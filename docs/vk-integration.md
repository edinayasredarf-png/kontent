# Интеграция ВКонтакте

Проверено по официальной документации (dev.vk.com, схема VKCOM/vk-api-schema) в октябре 2026. Что не удалось проверить, помечено отдельно.

## Как устроено в проекте

| Что | Где |
|---|---|
| Канал публикации VK (ключ сообщества) | `kz_channels` (kind `vk`), секреты зашифрованы (`src/lib/crypto.ts`) |
| Личное подключение (VK ID, ключ пользователя) | `kz_vk_connections` (миграция `db/022_vk_connections.sql`), `kz_channels.connection_id` |
| Очередь и повторы публикаций | `kz_publications` + воркер в `src/lib/pipeline.ts` (статусы queued/sending/published/failed, попытки, ручной повтор) |
| Провайдер VK | `src/lib/publishing/vk.ts` |
| Подключение, обновление токена, сообщества | `src/lib/vk-connect.ts`, `src/lib/vk-actions.ts` |
| Маршруты OAuth | `/api/vk/connect/start`, `/api/vk/connect/callback` |
| Интерфейс | карточка «ВКонтакте: личное подключение» на странице «Каналы» |
| Автопубликация и расписание | настройки завода («Публикация», время выхода) — существующий механизм, VK-каналы выбираются так же, как остальные |

Отдельных таблиц `social_*` не создавалось: публикации, повторы и история уже есть в `kz_publications`.

## Что говорит документация VK (важные ограничения)

* `wall.post`, `photos.getWallUploadServer`, `photos.getUploadServer`, `video.save`: для ключа **пользователя** нужны права `wall`, `photos`, `video`, которые VK выдаёт **«в исключительных случаях через запрос в поддержку»** (devsupport@corp.vk.com). Обычному приложению они не выдаются автоматически.
* Ключ **сообщества**: `photos.getWallUploadServer` и `video.save` недоступны (ошибка 27 «method is unavailable with group auth»). Разрешены `photos.getMessagesUploadServer` / `photos.saveMessagesPhoto` (право «Фотографии», нужны включённые сообщения сообщества) и `docs.getWallUploadServer` / `docs.save` (право «Файлы»).
* На практике фото, загруженное через «сообщения», `wall.post` принимает, но на стене оно **не показывается** (проверено на реальном сообществе). `wall.getById` ключом сообщества недоступен (27), поэтому проверить пост ключом сообщества нельзя.
* `wall.editAdsStealth` — редактирование скрытых рекламных записей (право `ads`, тоже по запросу в поддержку). К обычной публикации отношения не имеет и не используется. Публикует `wall.post`.
* `wall.post`: до 10 медиа в записи; параметр `guid` защищает от повторной отправки одной записи (действует час) — используем его с ключом `kz_publications.id`, поэтому повтор после неясного таймаута не создаёт дубль.
* `video.save`: не более 5000 вызовов в сутки.

## VK Клипы

В официальном каталоге методов (464 метода) и в схеме `vk-api-schema` метода для создания/публикации клипа **нет**. В сторонних источниках упоминается `shortVideo.create`, но в официальной документации он не описан и его параметры подтвердить нельзя. Неофициальные методы, автоматизацию браузера и обходы мы не используем, поэтому **публикация VK Клипов не реализована**. Видео, загруженное обычным способом, VK сам может показать в клипах (если оно вертикальное и короткое), повлиять на это нельзя.

Видеопубликация обычным видео (`video.save` → загрузка → ожидание обработки → запись с `video{owner}_{id}`) реализована в провайдере (`uploadVideo`, `PublishInput.video`) и покрыта тестами с поддельным VK, но **в интерфейсе нет источника видеофайлов**: сервис видео не создаёт («Сценарий ролика» — текст), поэтому кнопки «Опубликовать видео» нет. Работает только с ключом пользователя с правом `video`. Имя поля файла при загрузке (`video_file`) взято из практики, а не из подтверждённой страницы документации.

## Настройка

1. Приложение VK ID: <https://id.vk.com> → создать приложение (тип «Веб»), получить ID приложения. В «Доверенных redirect URL» добавить `https://<ваш-домен>/api/vk/connect/callback` (и тот же адрес для входа: `/api/oauth/vk/callback`).
2. Права для публикации от имени пользователя запрашиваются параметром `VK_PUBLISH_SCOPE` (по умолчанию `wall photos video groups`). Сами права приложению нужно получить у поддержки VK; без них подключение завершится ошибкой или токен не сможет публиковать. Формат названий прав в VK ID не удалось проверить по документации (страница VK ID не отображалась), при необходимости задайте значение вручную.
3. Переменные окружения: `VK_CLIENT_ID` (цифры), `APP_URL` (основной адрес сайта без слэша; нужен для redirect URI и для публичных ссылок на картинки), `AUTH_SECRET` или `CHANNEL_SECRET` (ключ шифрования токенов). Необязательно: `VK_PUBLISH_SCOPE`, `VK_ID_BASE`, `VK_API_BASE` (для тестов).
4. Миграция: выполнить `db/adminer-schema.sql` (или `npm run db:migrate`) — добавляется `022_vk_connections.sql`.
5. Подключение: «Каналы» → «Подключить ВКонтакте» → разрешить доступ → «Сообщества» → выбрать бренд → «Подключить как канал». «Проверить» проверяет ключ, «Отключить» стирает токены и останавливает связанные каналы.

Подключение через ключ сообщества (как раньше) остаётся: «Добавить канал» → ВКонтакте.

## Безопасность

* Токены (access, refresh, device_id) хранятся только в `kz_vk_connections.secrets` в зашифрованном виде (AES-256-GCM), клиенту не отдаются, в логи не пишутся (ошибки логируются без кодов и токенов).
* OAuth: `state` и PKCE-verifier в httpOnly-cookie, привязанной к пользователю и организации; в callback проверяются совпадение state, пользователь, организация, активная сессия и право записи.
* Все запросы по подключению идут с условием `org_id` текущей организации; чужое подключение подменой id использовать нельзя (покрыто тестом).
* Сообщество при подключении как канал перепроверяется на сервере по ответу VK, а не по данным из браузера.
* Истёкший токен обновляется по refresh-токену; при отзыве прав подключение и каналы получают статус «нужна повторная авторизация», задания не повторяются вслепую.

## Тесты

```
npm test                                  # провайдер VK (без БД)
TEST_DATABASE_URL=postgres://… npm test   # + подключение, токены, изоляция (временная БД с применённой adminer-schema.sql)
```

Реальные запросы к VK тесты не делают (поддельный сервер `tests/mock-vk.ts`).

## Что не проверено на настоящем VK

Весь обмен с VK ID и API проверен только на поддельном сервере. Не проверены: выдача прав `wall/photos/video` приложению, формат refresh-запроса VK ID, публикация фото личным ключом, видео, показ карточки-ссылки (VK ранее отвечал `link_photo_sizing_rule` — для этого превью теперь строится в формате 1200×630).
