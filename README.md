# Контент-завод (lontent)

Next.js 15 + Tailwind 4 + Postgres. Мультитенантная платформа: организации → бренды → заводы → материалы.

## Локально
```bash
cp .env.example .env.local   # заполнить DATABASE_URL, AUTH_SECRET, ANTHROPIC_API_KEY
npm i && npm run db:migrate && npm run dev
```

## Деплой на Vercel
1. `npx vercel link` → создать проект, Root Directory — корень этого репозитория.
2. Env:
   - `DATABASE_URL` — можно та же Timeweb-БД, что у единойсреды: все таблицы проекта с префиксом `kz_`, чужие не затрагиваются. Те же `DATABASE_SSL_*`, если они там заданы (`DATABASE_SEARCH_PATH` не нужен)
   - `AUTH_SECRET` (`openssl rand -base64 32`), опционально `CHANNEL_SECRET` для шифрования токенов каналов
   - `SELFHOSTED_LLM_URL`, `SELFHOSTED_LLM_API_KEY`, `SELFHOSTED_LLM_MODEL` — AI Gateway Timeweb, **значения те же, что в проекте единойсреде.рф**
   - `CRON_SECRET` — секрет для воркера
   - `PLATFORM_ADMIN_EMAILS` — кто видит «Настройки ИИ» (выбор моделей по задачам)
3. Миграции: `DATABASE_URL=… npm run db:migrate` с локальной машины.
4. Домен: Vercel → Settings → Domains → `kontent.единаясреда.рф` (punycode: `kontent.xn--80aakbcct4b2aj7m.xn--p1ai`). У DNS-хостинга домена добавить CNAME `kontent` → `cname.vercel-dns.com`.

## Домен juicerai.ru и прокси
Vercel режет российские IP, поэтому российские посетители заходят через свой nginx-прокси (папка `deploy/docker-proxy` проекта «Опора», сервер 94.198.217.44). Прокси ничего не знает о проекте: он по имени хоста пересылает запрос на Vercel, который выбирает проект по домену.
1. **Vercel** → проект → Settings → Domains → добавить `juicerai.ru` и `www.juicerai.ru`. Статус «Invalid Configuration» до смены DNS нормален.
2. **DNS у регистратора:** A-записи `juicerai.ru` и `www` → `94.198.217.44` (IP прокси, не Vercel).
3. **Сервер прокси** (от root, из `deploy/docker-proxy`): `sudo bash setup.sh EMAIL juicerai.ru` — выпустит сертификаты Let's Encrypt для `juicerai.ru` и `www.juicerai.ru`, добавит конфиг и перезагрузит nginx. Существующие домены не затрагиваются, `PROXY_SECRET` переиспользуется (`cat data/proxy.secret`).
4. **Vercel → Environment Variables:** `APP_URL=https://juicerai.ru`, `PROXY_SECRET=<значение из proxy.secret>`; затем Redeploy. Без `PROXY_SECRET` все посетители для сайта будут «одним IP» (ограничитель попыток входа сработает на всех сразу).
5. **Провайдеры входа:** добавить `https://juicerai.ru` в Яндекс ID и VK ID (Callback `https://juicerai.ru/api/oauth/<провайдер>/callback`, для Яндекса ещё `https://juicerai.ru/suggest/token`).
6. **Воркер:** в cron-job.org обновить адрес на `https://juicerai.ru/api/cron/tick`.
7. Проверка: `curl -sI https://juicerai.ru/ | head -3`; в админке платформы строка «APP_URL» должна показывать новый адрес.

## Воркер (cron)
`GET/POST /api/cron/tick` с заголовком `Authorization: Bearer $CRON_SECRET`. За проход: одобряет идеи автозаводов → пополняет план → пишет тексты по наступившим датам → ставит в очередь по расписанию → отправляет в Telegram/VK с ретраями (3 попытки, 5/10 мин).
Vercel Hobby даёт cron раз в сутки (`vercel.json`) — это страховка. Основной вызов: cron-job.org каждые 5 минут на `https://kontent.единаясреда.рф/api/cron/tick` с этим заголовком.

## Каналы
- **Telegram:** бот от @BotFather, добавить админом канала; в форме — токен и `@канал`.
- **VK:** сообщество → Управление → API → ключ доступа с правом «стена»; в форме — ключ и числовой id сообщества.
Токен проверяется перед сохранением и хранится зашифрованным (AES-256-GCM).

## Вход через Яндекс ID и VK ID
Используются **официальные виджеты**: кнопка Яндекс ID (SDK `YaAuthSuggest`) и VK ID OneTap (`@vkid/sdk`). Токен из браузера сервер проверяет у провайдера (`/api/auth/yandex-id`, `/api/auth/vk-id`), у токена Яндекса сверяется `client_id`. Если виджет не загрузился, через 7 секунд появляется запасная ссылка со входом редиректом (`/api/oauth/<провайдер>/start`, PKCE).
- **Яндекс:** `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`. В приложении Яндекса: Callback URI `https://<домен>/suggest/token` (для кнопки) и `https://<домен>/api/oauth/yandex/callback` (запасной вход); Suggest Hostname — `https://<домен>`.
- **VK:** приложение VK ID, нужен только `VK_CLIENT_ID`. Базовый домен и Redirect URL: `https://<домен>` и `https://<домен>/api/oauth/vk/callback`. Необязательно `VK_SCOPE` (например `email`).
- `<домен>` = `kontent.xn--80aakbcct4b2aj7m.xn--p1ai` (punycode).

## Мониторинг источников
Раздел «Мониторинг»: сайты/RSS, публичные Telegram-каналы (через `t.me/s/…`, без токена), сообщества VK (нужен `VK_SERVICE_TOKEN` на сервере), новости по запросу (Google News) и ручное добавление постов (MAX, закрытые каналы). Читать чужие каналы MAX автоматически нельзя — открытого способа нет.
Посты сортируются по совпадению с ключевыми словами, из поста одной кнопкой делается идея в контент-плане завода или сразу материал. Воркер опрашивает источники раз в час. Миграция: `db/005_monitoring.sql` (есть в `adminer-schema.sql`).
Адреса вводит пользователь, поэтому серверные запросы защищены от SSRF (`src/lib/safefetch.ts`): только http/https, порты 80/443, проверка IP при соединении, ручной контроль редиректов. `ALLOW_PRIVATE_FETCH=1` — только для локальных тестов, в проде не задавать.

## Брендбук и картинки
Страница бренда (`/app/brands/<id>`): цвета, стиль, «всегда/никогда на картинках», логотип, фото продукта, референсы. Файлы хранятся в БД (`kz_assets`), отдаются только участникам своей организации через `/api/assets/<id>`; при загрузке перекодируются (метаданные вырезаются, SVG не принимается), лимит 4 МБ на файл и 150 МБ на организацию.
Референсы и фото продукта описываются vision-моделью, описание уходит в промпт. Логотип накладывается на готовую картинку программно, а не рисуется нейросетью. Картинку делает модель из «Настроек ИИ» → «Генерация изображений» через `/images/generations` шлюза (если модель так не работает, пробуется чат-вариант). Цена — `PRICES.image`. В заводе включается «Картинки к материалам»; в Telegram и VK картинка уходит вместе с постом.
Миграция: `db/006_brandkit_images.sql`. Генерация видео пока не подключена: в настройках можно выбрать модель, но вызова API видео нет.

## Порядок обновления (важно)
Vercel выкатывает код сразу после пуша, а схема БД обновляется вручную. Поэтому после **каждого** обновления, где появилась новая миграция в `db/`, выполните `db/adminer-schema.sql` в Adminer (он накопительный и безопасен для повторного запуска). Пока схема отстаёт, кабинет показывает страницу «Нужно обновить базу данных», а `/api/health` перечисляет недостающие миграции. Новые миграции нужно добавлять в `src/lib/migrations.ts` и в `adminer-schema.sql`.

## Админка платформы, сброс пароля, юридические страницы
- **Админка** `/app/admin` (только email из `PLATFORM_ADMIN_EMAILS`): обзор и состояние системы, организации (ручное пополнение и списание баланса, смена тарифа, приостановка), пользователи (блокировка, «выйти везде», ссылка сброса пароля), журнал действий. Миграция `db/010_admin_reset_legal.sql`.
- **Сброс пароля** `/forgot` → письмо со ссылкой на `/reset/<токен>` (час, одноразовая). Почта: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` — те же имена, что на единойсреде. Без SMTP администратор выдаёт ссылку вручную.
- **Юридические страницы** `/legal/privacy`, `/legal/terms`, `/legal/cookies`: шаблоны. Реквизиты оператора — `LEGAL_NAME`, `LEGAL_INN`, `LEGAL_OGRN`, `LEGAL_ADDRESS`, `LEGAL_EMAIL`, `LEGAL_PHONE`. **Тексты нужно проверить у юриста**; версия документов — `LEGAL_VERSION` в `src/lib/legal.ts`, при регистрации сохраняется согласие (время и версия).
- **Логотип:** `public/logo-light.svg` (чёрный шрифт, светлая тема) и `public/logo-dark.svg` (белый шрифт, тёмная тема), без подложки; какой показан — решает CSS (`.logo-light`/`.logo-dark`). Иконка вкладки — `src/app/icon.svg` (исходный `favicon.svg`), `src/app/favicon.ico` (16/32/48 px) и `src/app/apple-icon.png` (180 px, тёмный фон) — Next подключает их сам.

## Тема оформления
Светлая, тёмная или «как в системе» — выбор в «Профиль и настройки», хранится в аккаунте (`kz_users.theme`, миграция `011_theme.sql`) и дублируется в cookie `lt_theme`, чтобы тема применялась до отрисовки страницы (скрипт в `<head>` в `src/app/layout.tsx`). Палитры — переменные в `src/app/globals.css`: явный выбор через `data-theme`, «как в системе» через `prefers-color-scheme`. В новой вёрстке вместо `bg-white` используйте `bg-surface`, цвета — только токены (`bg-tile`, `text-ink`, `border-line` и т. д.).

## Карусели и настройки постов
Карусель — набор картинок-слайдов (1080×1350 или 1080×1080). Текст набирается самим сервисом (шрифт Inter переводится в контуры через opentype.js, затем sharp → JPEG), поэтому кириллица всегда чёткая и системные шрифты не нужны. Слайды хранятся в `kz_assets` (`item_id`, `position`; `-1` — фон обложки от нейросети), миграция `012_carousel_assets.sql`. Цена: карусель 35 ₽, обложка нейросетью +15 ₽. Публикация: Telegram — альбом, VK — несколько вложений, webhook — массив `images`; ZIP со слайдами — `/api/export/[id]/carousel`.
Настройки постов завода (типы, длина, примеры, ссылка, призыв, эмодзи, хештеги, число слайдов, стиль карусели) лежат в `kz_factories.brief` и применяются в плане и при написании (`src/lib/postsettings.ts`).

## Клиентский портал, самообучение, ниши (миграция 013)
- **Доступ для клиента** (страница бренда): ссылка `/share/<токен>` без регистрации — клиент видит готовые материалы (тексты, слайды), одобряет, просит правки или комментирует, и смотрит отчёт за 30 дней (просмотры, реакции, подписчики, лучшие публикации). Токен хранится зашифрованным, поиск по хешу; ссылку можно отозвать, задать срок, включить «публиковать сразу после одобрения». Ответы видны в заводе у материала. Лимит 30 ответов в час на ссылку.
- **Самообучение**: перед планом и написанием материала в промпт добавляются выводы из статистики бренда (`learnings()` в `src/lib/engage.ts`, от 6 постов со статистикой). Выключается галочкой в настройках контента завода.
- **Подписчики**: воркер раз в сутки записывает число подписчиков Telegram и VK (`kz_channel_stats`), рост виден в «Аналитике» и в отчёте клиента.
- **Шаблоны ниш** (`src/lib/niches.ts`): при создании бренда и завода выбор ниши заполняет профиль и настройки.
- **Редактор карусели**: порядок, добавление и удаление слайдов, своя картинка для обложки.
- Схема для Adminer собирается командой `node scripts/gen-schema.mjs`.

## Контент из одного источника
В заводе: «Контент из одного источника» — ссылка на статью или вставленный текст (от 400 знаков) → 3–10 идей с разными углами (`repurposeSource` в `src/lib/pipeline.ts`, разбор страницы в `src/lib/repurpose.ts`). Источник хранится в `meta.source` каждой идеи, поэтому посты и карусели пишутся по его фактам. Цена: 3 ₽ за идею, при сбое или неполном ответе модели возврат; сами материалы оплачиваются при генерации. Модель задаётся задачей «Идея из поста-источника». Миграций нет.

## Макеты слайдов, подписи, повторы, календарь, API (миграция 014)
- **Макеты слайдов** (`src/lib/carousel/layouts.ts`): цифра крупно, список, было/стало (миф/факт), цитата. ИИ сам выбирает макет у части слайдов, `fixLayout` откатывает негодные к обычному; в редакторе макет выбирается вручную.
- **Подпись канала** (страница «Каналы»): фирменная концовка в конце каждого поста и карусели в этот канал, не в SEO-статьи (`withSignature`).
- **Повтор материалов**: у опубликованного поста или карусели «Повторять раз в N дней, до 5 раз». Воркер (`spawnRepeats`) создаёт копию в статусе «готов», пока прошлая копия не вышла — новая не создаётся.
- **Календарь**: материалы, не ушедшие в публикацию, переносятся перетаскиванием на другой день (на телефоне — через «Изменить дату» в заводе).
- **Публичный API** `/api/v1/*` (страница «API и интеграции»): ключи `lt_…` (хранится только хеш, показывается один раз), роли «чтение» и «чтение и запись», лимит 60 запросов в минуту на ключ. Методы: me, brands, factories, items (список, создание идеи или готового поста, публикация), plan, repurpose, stats.

## Рост и работа с аудиторией (миграция 015)
- **Форматы**: опрос (в Telegram встроенный опрос, в остальных площадках текст с цифрами), конкурс, инфографика (шаги / цифры / чек-лист, рисуется у нас как слайды карусели).
- **Входящие**: тон комментария определяется при сборе без нейросети (спам, негатив, вопрос, позитив), фильтры и «скрыть весь спам»; «Ответ от ИИ» (3 ₽) подставляет черновик в поле ответа. Ответы возможны только во VK; Telegram Bot API комментарии каналов не отдаёт.
- **Ссылки и переходы**: настройка завода «Ссылки на ваш сайт в постах» — UTM-метки или UTM плюс короткая ссылка `/go/<код>` со счётчиком кликов (боты не считаются). Меняются только ссылки на хост из поля «Ссылка на сайт или товар». Клики видны в «Аналитике».
- **Развитие материала**: «Ещё 5 идей в духе этого», A/B-вариант текста (выходит на день позже, сравнение просмотров после суток, разница меньше 10% — ничья), версии под площадки (в канал уходит текст его площадки).
- **Стратегия и рубрики**: ИИ (10 ₽) или вручную; план распределяет идеи по рубрикам, у материала в промпте его рубрика, в заводе матрица «рубрика × неделя».
- **Конкуренты** (`/app/competitors`): публичные каналы Telegram (через t.me/s) и сообщества VK (нужен `VK_SERVICE_TOKEN`), обновление каждые 12 часов в воркере, сравнение, разбор ИИ и «в план».
- Исправлено: `toPlain` убирал «#» у хештегов в начале строки (считал заголовком markdown).

## SEO-статьи
`genSeoArticle` (`src/lib/seo.ts`): статья пишется ЦЕЛИКОМ одним запросом (лимит ответа 8000 токенов, до 120 с) — так текст связный. Если вышло короче 1100 слов, модель получает весь готовый текст и дописывает в него разделы перед заключением (до двух раундов). Только если цельная генерация не удалась (ошибка модели, таймаут), включается последовательный режим: план, затем вступление и разделы по порядку, каждый видит уже написанный текст. Форматы: «Лонгрид (текст)» — обычный длинный текст, «SEO-статья для сайта» — HTML с мета-полями и SEO-проверкой.

## Создание материалов
В заводе блок «Создать материал»: тема + выбор типов (пост, карусель, SEO-статья, опрос и т. д.). Режим «сразу» создаёт сами материалы без карточек-идей (первые три в этом запросе, остальные в фоне), режим «в план» — только идеи-карточки. Карточки-идеи также создают «Идея-карточка в план», «Список идей», «Продлить план» и «Контент из одного источника».

## Визуальный редактор, белая метка, PDF-отчёт, рассылки и гайды (миграция 016)
- **Визуальный редактор слайдов** (`src/components/SlideEditor.tsx`): поверх готового слайда карусели, инфографики или картинки поста добавляются текст, фигуры и свои картинки; слои двигаются и масштабируются, есть цвета бренда, прозрачность, порядок, отмена. Холст рисуется в браузере и сохраняется как JPEG (`/api/editor/save`). Слайды с ручной правкой помечены ✎ и не перерисовываются при смене стиля или других слайдов, пока их текст не изменён; «Вернуть слайд» возвращает автооформление.
- **Белая метка**: на странице бренда «Оформление от имени агентства» (имя агентства, подпись, скрыть упоминание платформы). Клиентский портал и отчёт показывают логотип и цвета бренда клиента, без плашки cookie и без описания платформы.
- **PDF-отчёт клиента**: `/share/<токен>/report` (период 7/30/90 дней), оптимизирован под печать; кнопка «Сохранить как PDF» открывает печать браузера.
- **Рассылка (email)** и **гайд / лид-магнит**: рассылка — тема, прехедер, заголовок, текст, кнопка, готовый HTML 600 px с `{{unsubscribe_url}}`, просмотр, скачивание, копирование, тест на свою почту через SMTP; гайд — цельный документ 1200–1800 слов с оглавлением и чек-листом, страница для печати и PDF. В соцсети не публикуются. Рассылка подписчикам из сервиса не отправляется (нужен ваш сервис рассылок и согласия получателей).

## Выгрузка контента
- **Копирование**: иконка в строке каждого материала и кнопки в карточке («Копировать текст», «Копировать HTML» для SEO, рассылок и гайдов, «Копировать подпись» у карусели, «Копировать версию» у версий под площадки). Если браузер не даёт писать в буфер, открывается окошко с выделенным текстом.
- **Скачать материал** (`/api/export/<id>/file?format=txt|md|docx|html|zip`): текст, Markdown, Word (собирается без библиотек из заголовков и абзацев), HTML для SEO-статьи, рассылки и гайда, ZIP с текстом и картинками. Логика в `src/lib/exporter.ts`.
- **Выгрузить всё** по фильтру завода (`/api/export/factory/<id>?format=csv|zip&kind=&status=&from=&to=`): CSV для Excel (UTF-8 с BOM, разделитель «;», до 300 материалов) или ZIP по папке на материал (до 120 материалов и 40 МБ, остальные перечисляются в `НЕ_ВОШЛИ.txt`).

## Чтение каналов MAX (миграция 017)
По документации dev.max.ru бот видит посты канала только если он администратор с правом «читать все сообщения»; читать чужие открытые каналы MAX нельзя. Поэтому MAX работает как источник для своих каналов и каналов партнёров, добавивших вашего бота. Реализация: `listPosts` (GET /messages с chat_id, опрос воркером, без вебхука) и `discoverChats` (GET /updates: список каналов бота по событиям, потому что отдельного метода списка нет, а GET /chats с июня 2026 не поддерживается) в `src/lib/publishing/max.ts`; источник мониторинга типа «MAX» (`src/lib/monitor/fetchers.ts`), вложения постов сохраняются в `kz_feed_items.media`. Домен API: `platform-api2.max.ru`. Дальше по документации: вебхук `POST /subscriptions` (HTTPS, секрет в заголовке `X-Max-Bot-Api-Secret`, ответ 200 за 30 с, до 10 повторов) для мгновенной реакции вместо опроса и события `comment_created` для модерации комментариев.

## Автолента (миграция 018)
Поток «источники → отбор → пересказ → публикация» (`src/lib/flows/`, страница `/app/flows`). Источники берутся из «Мониторинга» (Telegram, VK, сайты и RSS, MAX своих каналов), для активных потоков они опрашиваются каждые 5 минут. Конвейер на новость (`run.ts`): нет текста, стоп-слова и обязательные слова, реклама по пометкам (`erid`, «на правах рекламы», рекламные формулировки) → дубли (сходство текстов по шинглам; пограничное 0,22–0,6 решает нейросеть-судья) → разбор нейросетью (тип, тема, масштаб, «нашесть», регион, реклама) и фильтры потока → пересказ в голосе канала с проверкой, что текст не близок к оригиналу (иначе «copy» и отбраковка) → очередь на одобрение или автоматический выпуск с суточным лимитом, паузой между постами и тихими часами (МСК). Публикация создаёт материал без завода (`meta.channelIds`) и использует общую очередь каналов; картинки: нет, своя нейросетью или из источника (с предупреждением о правах). У каждой новости видны статус и причина отбраковки; «Это нам надо» возвращает отбракованную в очередь. Цены: разбор 0,5 ₽, пересказ 2 ₽, проверка дубля 0,3 ₽. Не хватает денег — поток останавливается с пометкой, новости не теряются. Фото из источников извлекаются для Telegram (t.me/s), VK и RSS; видео не копируются.

## ИИ-ассистенты (каталог инструментов студии)
`src/lib/studio-catalog.ts`: 17 текстовых инструментов на шаблонах заданий (финальный абзац, публикация из плана, вывод по тексту, холодное письмо, совет главреда, тред для X и Threads, набор эмодзи, идеи Highlights, идеи рассылок, вопросы для подкаста, план прямого эфира, идеи трипвайера, описание профиля, идеи опросов, перевод, прогрев для Stories); плюс «Текст по изображению» (vision-модель, картинка сжимается в браузере и уходит data:URL, лимит server actions 2 МБ) и бесплатный «Рандомайзер» (crypto.randomInt, без нейросети). 22 стиля текста и 13 языков добавляются в системную подсказку. ## Мониторинг: полный текст, подборка, слова с ИИ (миграция 019)
- **Полный текст статьи** (`src/lib/monitor/news.ts`): RSS отдаёт только заголовок и анонс, поэтому при опросе сайтов для свежих новостей с коротким анонсом (до 3 за проход) страница открывается, из неё берётся основной текст (`<article>` или `<main>`, без меню и подвала) и сохраняется в `kz_feed_items.full_text`. Кнопка «Прочитать полностью» делает то же по требованию. Для Telegram, VK и MAX текст уже полный. Google Новости текст не отдают (статус `unsupported`).
- **Создать материал из новости**: в карточке новости выбираются завод, типы материалов (пост, карусель, SEO-статья, опрос и т. д.) и режим «сразу» или «в план». Источник (до 8000 знаков полного текста, адрес) хранится в материале; генераторы теперь получают из него 3000–6000 знаков вместо 1500–3000.
- **Подборка новостей** (6 ₽): нейросеть оценивает до 40 свежих новостей по профилю бренда и продуктам заводов (0–10) и пишет угол подачи; фильтр «Подходит мне».
- **Ключевые слова с ИИ** (3 ₽) на странице «Источники и слова»: слова в начальной форме (поиск сам находит падежи), с пояснением и стоп-словами; уже добавленные не предлагаются.

## Индикаторы ожидания и «чипы»
- **Кнопки отправки** (`src/components/SubmitButton.tsx`, на `useFormStatus`): во время действия блокируются и показывают спиннер; кнопки в `<form action>` по всему кабинету заменены кодмодом (90 штук). `Form` тоже регистрирует ожидание.
- **Общая полоса и подсказка** (`PendingBar`, `lib/pending-store.ts`): тонкая полоса сверху при любом ожидании, через 2 секунды подсказка «Работаем… может занять до минуты». `NavProgress` включает полосу при переходах по ссылкам и отправке GET-форм (слушатели в фазе перехвата, иначе `Link` отменяет клик раньше).
- **Скелетоны** `loading.tsx`: общий для кабинета и отдельные для завода, мониторинга, аналитики и ассистентов.
- **Переключаемые чипы** (`.chip-toggle` в `globals.css`): выбранный подсвечен рамкой, цветом и галочкой. Раньше подсветка не работала: правило `.chip` без слоя Tailwind перебивало утилиты `has-[:checked]`.

## База знаний бренда

Раздел «Бренды → База знаний» (`/app/brands/<id>/knowledge`). Сюда загружают материалы о компании: свои статьи и посты, описания услуг, сравнения с конкурентами, кейсы, вопросы клиентов. Источники: вставленный текст, ссылки (страница скачивается и сохраняется как текст), файлы `.txt/.md/.docx/.html` до 4 МБ.

- Кнопка «Проанализировать» запускает нейросеть (задача `analyst`): выжимка по каждому новому материалу → сведение в единый профиль (чем занимаемся, продукты, УТП, преимущества, конкуренты, факты, возражения, термины, что нельзя утверждать) + отдельный разбор стиля письма по материалам с пометкой «Образец стиля». Уже разобранные материалы повторно не обрабатываются, за один запуск — до 6 новых (остальные следующим нажатием). Цены: `kbDigest`, `kbMerge`, `kbStyle`, `kbTest` в `src/lib/wallet.ts`.
- Профиль и стиль можно править руками; «Проверить стиль» пишет пробный пост.
- `kbBlock(profile, style, topic)` (`src/lib/kb/use.ts`) добавляется в `brandBlock` через `BrandCtx.kb`: подбираются самые близкие теме факты и возражения, размер ограничен. Подключено: контент-план, посты/карусели/инфографика/опросы/рассылки/гайды/SEO, повторное использование источника, рост (варианты, ремикс), стратегия, студия, ответы на комментарии, автолента, подборка новостей.
- Лимиты: 40 материалов на бренд, 60 000 знаков в материале. Миграция `020_brand_kb.sql` (`kz_brand_docs`, `kz_brand_kb`) — выполнить `db/adminer-schema.sql` в Adminer.

## Редизайн: чат-ассистент и новое меню (ветка `redesign`, миграция 021)

- Главная страница `/app` теперь чат (`src/components/Chat.tsx`, `src/lib/agent/*`). Ассистент сам вызывает инструменты: сводка по аккаунту, новости, источники, аналитика, заводы, материалы (чтение, бесплатно для данных), обновление источников (выполняется сразу). Изменения (включить источник, настройки завода, создать материалы из новости, продлить план) только предлагаются кнопкой и выполняются после нажатия; параметры берутся из сохранённого сообщения, чужие id отбрасываются. Ссылки на разделы проходят белый список (`cleanHref`). Ответ стоит `PRICES.idea` (3 ₽), история хранится в `kz_chat_messages`.
- Меню: Чат, Заводы, Бренды, Календарь, Автолента, Конкуренты, Входящие, Публикации, Аналитика, ИИ-ассистенты. Остальное в `/app/settings` (каналы, мониторинг, баланс, команда, профиль, партнёрка, API, администрирование). Старый «Обзор» теперь `/app/overview`, настройки ИИ `/app/settings/ai`.
- Шрифт Involve: положите `Involve-Regular/Medium/SemiBold/Bold.woff2` в `public/fonts`, пока файлов нет, используется Inter. Логотипы: `public/logo-main.svg`, `logo-main-dark.svg`.
