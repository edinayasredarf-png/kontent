# Контент-завод (lontent)

Next.js 15 + Tailwind 4 + Postgres. Мультитенантная платформа: организации → бренды → заводы → материалы.

## Локально
```bash
cp .env.example .env.local   # заполнить DATABASE_URL, AUTH_SECRET, ANTHROPIC_API_KEY
npm i && npm run db:migrate && npm run dev
```

## Деплой на Vercel
1. `npx vercel link` → создать проект, Root Directory — корень этого репозитория.
2. Env:
   - `DATABASE_URL` — можно та же Timeweb-БД, что у единойсреды: все таблицы проекта с префиксом `kz_`, чужие не затрагиваются. Те же `DATABASE_SSL_*`, если они там заданы (`DATABASE_SEARCH_PATH` не нужен)
   - `AUTH_SECRET` (`openssl rand -base64 32`), опционально `CHANNEL_SECRET` для шифрования токенов каналов
   - `SELFHOSTED_LLM_URL`, `SELFHOSTED_LLM_API_KEY`, `SELFHOSTED_LLM_MODEL` — AI Gateway Timeweb, **значения те же, что в проекте единойсреде.рф**
   - `CRON_SECRET` — секрет для воркера
   - `PLATFORM_ADMIN_EMAILS` — кто видит «Настройки ИИ» (выбор моделей по задачам)
3. Миграции: `DATABASE_URL=… npm run db:migrate` с локальной машины.
4. Домен: Vercel → Settings → Domains → `kontent.единаясреда.рф` (punycode: `kontent.xn--80aakbcct4b2aj7m.xn--p1ai`). У DNS-хостинга домена добавить CNAME `kontent` → `cname.vercel-dns.com`.

## Воркер (cron)
`GET/POST /api/cron/tick` с заголовком `Authorization: Bearer $CRON_SECRET`. За проход: одобряет идеи автозаводов → пополняет план → пишет тексты по наступившим датам → ставит в очередь по расписанию → отправляет в Telegram/VK с ретраями (3 попытки, 5/10 мин).
Vercel Hobby даёт cron раз в сутки (`vercel.json`) — это страховка. Основной вызов: cron-job.org каждые 5 минут на `https://kontent.единаясреда.рф/api/cron/tick` с этим заголовком.

## Каналы
- **Telegram:** бот от @BotFather, добавить админом канала; в форме — токен и `@канал`.
- **VK:** сообщество → Управление → API → ключ доступа с правом «стена»; в форме — ключ и числовой id сообщества.
Токен проверяется перед сохранением и хранится зашифрованным (AES-256-GCM).

## Вход через Яндекс ID и VK ID
Используются **официальные виджеты**: кнопка Яндекс ID (SDK `YaAuthSuggest`) и VK ID OneTap (`@vkid/sdk`). Токен из браузера сервер проверяет у провайдера (`/api/auth/yandex-id`, `/api/auth/vk-id`), у токена Яндекса сверяется `client_id`. Если виджет не загрузился, через 7 секунд появляется запасная ссылка со входом редиректом (`/api/oauth/<провайдер>/start`, PKCE).
- **Яндекс:** `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`. В приложении Яндекса: Callback URI `https://<домен>/suggest/token` (для кнопки) и `https://<домен>/api/oauth/yandex/callback` (запасной вход); Suggest Hostname — `https://<домен>`.
- **VK:** приложение VK ID, нужен только `VK_CLIENT_ID`. Базовый домен и Redirect URL: `https://<домен>` и `https://<домен>/api/oauth/vk/callback`. Необязательно `VK_SCOPE` (например `email`).
- `<домен>` = `kontent.xn--80aakbcct4b2aj7m.xn--p1ai` (punycode).

## Мониторинг источников
Раздел «Мониторинг»: сайты/RSS, публичные Telegram-каналы (через `t.me/s/…`, без токена), сообщества VK (нужен `VK_SERVICE_TOKEN` на сервере), новости по запросу (Google News) и ручное добавление постов (MAX, закрытые каналы). Читать чужие каналы MAX автоматически нельзя — открытого способа нет.
Посты сортируются по совпадению с ключевыми словами, из поста одной кнопкой делается идея в контент-плане завода или сразу материал. Воркер опрашивает источники раз в час. Миграция: `db/005_monitoring.sql` (есть в `adminer-schema.sql`).
Адреса вводит пользователь, поэтому серверные запросы защищены от SSRF (`src/lib/safefetch.ts`): только http/https, порты 80/443, проверка IP при соединении, ручной контроль редиректов. `ALLOW_PRIVATE_FETCH=1` — только для локальных тестов, в проде не задавать.

## Брендбук и картинки
Страница бренда (`/app/brands/<id>`): цвета, стиль, «всегда/никогда на картинках», логотип, фото продукта, референсы. Файлы хранятся в БД (`kz_assets`), отдаются только участникам своей организации через `/api/assets/<id>`; при загрузке перекодируются (метаданные вырезаются, SVG не принимается), лимит 4 МБ на файл и 150 МБ на организацию.
Референсы и фото продукта описываются vision-моделью, описание уходит в промпт. Логотип накладывается на готовую картинку программно, а не рисуется нейросетью. Картинку делает модель из «Настроек ИИ» → «Генерация изображений» через `/images/generations` шлюза (если модель так не работает, пробуется чат-вариант). Цена — `PRICES.image`. В заводе включается «Картинки к материалам»; в Telegram и VK картинка уходит вместе с постом.
Миграция: `db/006_brandkit_images.sql`. Генерация видео пока не подключена: в настройках можно выбрать модель, но вызова API видео нет.

## Порядок обновления (важно)
Vercel выкатывает код сразу после пуша, а схема БД обновляется вручную. Поэтому после **каждого** обновления, где появилась новая миграция в `db/`, выполните `db/adminer-schema.sql` в Adminer (он накопительный и безопасен для повторного запуска). Пока схема отстаёт, кабинет показывает страницу «Нужно обновить базу данных», а `/api/health` перечисляет недостающие миграции. Новые миграции нужно добавлять в `src/lib/migrations.ts` и в `adminer-schema.sql`.

## Админка платформы, сброс пароля, юридические страницы
- **Админка** `/app/admin` (только email из `PLATFORM_ADMIN_EMAILS`): обзор и состояние системы, организации (ручное пополнение и списание баланса, смена тарифа, приостановка), пользователи (блокировка, «выйти везде», ссылка сброса пароля), журнал действий. Миграция `db/010_admin_reset_legal.sql`.
- **Сброс пароля** `/forgot` → письмо со ссылкой на `/reset/<токен>` (час, одноразовая). Почта: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` — те же имена, что на единойсреде. Без SMTP администратор выдаёт ссылку вручную.
- **Юридические страницы** `/legal/privacy`, `/legal/terms`, `/legal/cookies`: шаблоны. Реквизиты оператора — `LEGAL_NAME`, `LEGAL_INN`, `LEGAL_OGRN`, `LEGAL_ADDRESS`, `LEGAL_EMAIL`, `LEGAL_PHONE`. **Тексты нужно проверить у юриста**; версия документов — `LEGAL_VERSION` в `src/lib/legal.ts`, при регистрации сохраняется согласие (время и версия).
- **Логотип:** `public/logo-light.svg` (чёрный шрифт, светлая тема) и `public/logo-dark.svg` (белый шрифт, тёмная тема), без подложки; какой показан — решает CSS (`.logo-light`/`.logo-dark`). Иконка вкладки — `src/app/icon.svg` (исходный `favicon.svg`), `src/app/favicon.ico` (16/32/48 px) и `src/app/apple-icon.png` (180 px, тёмный фон) — Next подключает их сам.

## Тема оформления
Светлая, тёмная или «как в системе» — выбор в «Профиль и настройки», хранится в аккаунте (`kz_users.theme`, миграция `011_theme.sql`) и дублируется в cookie `lt_theme`, чтобы тема применялась до отрисовки страницы (скрипт в `<head>` в `src/app/layout.tsx`). Палитры — переменные в `src/app/globals.css`: явный выбор через `data-theme`, «как в системе» через `prefers-color-scheme`. В новой вёрстке вместо `bg-white` используйте `bg-surface`, цвета — только токены (`bg-tile`, `text-ink`, `border-line` и т. д.).

## Карусели и настройки постов
Карусель — набор картинок-слайдов (1080×1350 или 1080×1080). Текст набирается самим сервисом (шрифт Inter переводится в контуры через opentype.js, затем sharp → JPEG), поэтому кириллица всегда чёткая и системные шрифты не нужны. Слайды хранятся в `kz_assets` (`item_id`, `position`; `-1` — фон обложки от нейросети), миграция `012_carousel_assets.sql`. Цена: карусель 35 ₽, обложка нейросетью +15 ₽. Публикация: Telegram — альбом, VK — несколько вложений, webhook — массив `images`; ZIP со слайдами — `/api/export/[id]/carousel`.
Настройки постов завода (типы, длина, примеры, ссылка, призыв, эмодзи, хештеги, число слайдов, стиль карусели) лежат в `kz_factories.brief` и применяются в плане и при написании (`src/lib/postsettings.ts`).

## Клиентский портал, самообучение, ниши (миграция 013)
- **Доступ для клиента** (страница бренда): ссылка `/share/<токен>` без регистрации — клиент видит готовые материалы (тексты, слайды), одобряет, просит правки или комментирует, и смотрит отчёт за 30 дней (просмотры, реакции, подписчики, лучшие публикации). Токен хранится зашифрованным, поиск по хешу; ссылку можно отозвать, задать срок, включить «публиковать сразу после одобрения». Ответы видны в заводе у материала. Лимит 30 ответов в час на ссылку.
- **Самообучение**: перед планом и написанием материала в промпт добавляются выводы из статистики бренда (`learnings()` в `src/lib/engage.ts`, от 6 постов со статистикой). Выключается галочкой в настройках контента завода.
- **Подписчики**: воркер раз в сутки записывает число подписчиков Telegram и VK (`kz_channel_stats`), рост виден в «Аналитике» и в отчёте клиента.
- **Шаблоны ниш** (`src/lib/niches.ts`): при создании бренда и завода выбор ниши заполняет профиль и настройки.
- **Редактор карусели**: порядок, добавление и удаление слайдов, своя картинка для обложки.
- Схема для Adminer собирается командой `node scripts/gen-schema.mjs`.

## Контент из одного источника
В заводе: «Контент из одного источника» — ссылка на статью или вставленный текст (от 400 знаков) → 3–10 идей с разными углами (`repurposeSource` в `src/lib/pipeline.ts`, разбор страницы в `src/lib/repurpose.ts`). Источник хранится в `meta.source` каждой идеи, поэтому посты и карусели пишутся по его фактам. Цена: 3 ₽ за идею, при сбое или неполном ответе модели возврат; сами материалы оплачиваются при генерации. Модель задаётся задачей «Идея из поста-источника». Миграций нет.
